## Definition of done (applies to every change)

1. It has an end-to-end test that fakes only the model and asserts what reaches Slack, the ledger or a Doc. A test that only checks that a part exists does not count.
2. It was seen working live: the Slack message, the card, the Doc link, or the run trace on the control page.
3. `doctor` passes and it was deployed with `deploy/push.sh` (one change per deploy).

## Proposal: formatted documents (approved to plan, not to build)

**Problem (class).** `docs_create` takes a title and plain text, so every document Ellie writes (resume, cover letter, memo, brief) arrives unformatted, and nothing can produce the DOCX and text-based PDF the resume framework requires. Check 3 also showed the content side: Ellie never read the framework (`📝 The Narrative Resume Framework`, Drive `/Resumes`), the `resume_builder/SKILL.md` it refers to no longer exists anywhere, and the contact line was invented.

**How chat assistants do it.** The model writes structure or code, a deterministic renderer applies the design, and the rendered pages are inspected as images before the file is handed over. Ellie has the model; she lacks the renderer and the visual check.

**Design (option D).**

1. **Structured document tool.** One tool, e.g. `document_render`, takes `{ kind, theme, title, blocks }`: blocks are heading, positioning line, paragraph, bullet list, role (title, employer, location, dates, bullets) and key/value lines, with inline bold. No HTML, no free-form styling: the model chooses words and structure, never fonts or sizes. The schema is shared by every document kind.
2. **Themes in code, rules in Docs.** A theme fixes page size, margins, fonts, sizes, accent colour and spacing. First theme: `executive-editorial` from the framework's Visual Design V3 (A4, one column, Aptos/Arial, name 20–23 pt, all-caps 10–11 pt headings, body 10.5–11 pt, 16–19 mm margins, accent `#17324D` or `#176B6B`, no tables, sidebars, text boxes, icons or images). Writing rules stay in the framework Doc so the owner can edit them without a deploy.
3. **Renderer on the VPS.** Blocks plus theme go to DOCX via the Node `docx` library, then to a text-based PDF via headless LibreOffice (`soffice --convert-to pdf`). Both files go to Drive (`/EllieOS/Projects/JOB_SEARCH/Resumes` or a folder chosen at build time); optionally an editable Google Doc converted from the DOCX.
4. **Visual and structural read-back (the verify hook).** Page count from the PDF (resume: exactly 2), text extraction compared with the block order (ATS reading order), and the pages rendered to PNG and checked by the model for overflow, orphaned headings and spacing. A failed check returns to the model once with the findings; a second failure reports BLOCKED with what is wrong, not "done".
5. **Sources, not memory.** A writing run reads the owner's working Docs before drafting. No Doc names, IDs or purposes are in code or config (these are working Docs that change often): Ellie lists the loose Google Docs in the folder that holds `ELLIE_CONFIG` (`/EllieOS`) and everything under its `Projects` folder (archives, run receipts and bot exports are excluded because they can repeat invented details) plus the already-linked record and Claims Bank, and picks what the task needs. Whether the resume framework moves into `/EllieOS` is the owner's call; until it does, Ellie does not see it.
6. **Claims check before rendering.** Every rendered document passes the shared claims guard, extended to identity details: email addresses, URLs, phone numbers, titles and years of experience must appear in an owner source, or the render is refused with the list of unverified items. This is class-level: Gmail drafts and Docs get the same check.

**Why not the alternatives.** A (Google Docs API styling): lighter, but limited to Docs styling, no true DOCX/PDF pair, Docs-to-PDF export shifts spacing. B (copy a template Doc and fill placeholders): pretty, but breaks with a variable number of roles and bullets. C (HTML to PDF with headless Chromium): most control, but no DOCX or editable Doc and it brings back chromium.

**Cost.** LibreOffice headless on the VPS (~500 MB disk, a few seconds per conversion), the `docx` npm package, and one PNG rasteriser (`pdftoppm` from poppler). The visual check adds one multimodal model call per render.
